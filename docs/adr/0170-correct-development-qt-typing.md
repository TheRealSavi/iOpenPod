# ADR-0170: Correct development Qt typing

- Status: Accepted
- Date: 2026-10-23

## Context

ADR-0094 retains PySide6 6.9.3 on macOS for the deployment target. Its bundled
annotations omit public fields and contain inaccurate decorator and nullable
return signatures. On macOS the locked Mypy reported 547 errors, largely caused
by these annotations; Pyright 1.1.414 reported 871 errors. Installing the community
PySide6-stubs 6.7.3.0 package also removes APIs introduced in Qt 6.9 from the type
checker view, so it is not a suitable replacement.

The developer explicitly wants both strict Pylance and Mypy checking. This
supersedes ADR-0003's decision to disable Pylance checking. The shared project
configuration and locked command-line tools remain in use.

## Decision

- Keep the existing platform-specific runtime dependencies and strict checks.
- Generate a local typing-only copy of the installed 6.9.3 stubs with
  `uv run python scripts/prepare_qt_typing.py`. Apply small, reviewed correction
  fragments to the existing APIs rather than substituting the newer Qt API surface.
- Backport field and signature information from the upstream 6.11.2 annotations;
  preserve the original 6.9 overloads and APIs outside the explicit corrections.
- Point Mypy and Pylance at the same ignored generated package under `typings/`.
  Do not modify site-packages, import the overlay at runtime, or ship it in the app.
- Treat generated third-party stubs like their installed originals: Mypy checks
  their application call sites, without reporting errors inside the library stubs.
  Application errors are not suppressed.
- Run preparation through the VS Code environment and type-check tasks. Use a
  portable `.venv` folder for VS Code's default interpreter setting.
- Gate corrections on the exact Qt version. Other versions use their own stubs,
  and preparation removes any stale overlay previously generated by this script.

## Consequences

macOS developers retain the deployed Qt runtime and get useful Qt completion and
checking without a new dependency. New environments and Qt upgrades require the
preparation step. The correction fragments need review when the Qt pin changes.
This is a focused backport of upstream annotations, not a complete audit of Qt's
typing; upstream assumptions about initialized public fields still apply.

Qt corrections are separate from native-platform API typing. Windows/Linux-only
standard-library exports are resolved at their existing native call boundaries
with explicit signatures, so macOS can check their callers without selecting a
different analysis platform. The default development environment also includes
the existing PyInstaller dependency so packaging hooks resolve in the editor.
Static checks on macOS do not replace native Windows runtime tests.
See [development typing](../../typings/README.md).
