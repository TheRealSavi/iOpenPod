Installation and first steps for iOpenPod on Windows, macOS, and Linux.

Native downloads for Windows, macOS, and Linux are available.

Install the latest iOpenPod release from GitHub, install from PyPI with uv, or get the Windows app from Microsoft Store. Other stores remain planned.

Native downloads

Native builds include Python and the application libraries. You do not need a separate Python installation. Choose the download for your operating system and processor.

Windows x64

  1. Open the latest release and download the asset ending in Windows-AMD64.zip for Windows 10 or 11 on an x64 PC.
  2. Extract iOpenPod.exe to a folder you can write to on a fixed NTFS drive, such as %LOCALAPPDATA%\Programs\iOpenPod. This location allows in-app updates; removable and network drives are not supported by the updater.
  3. Run iOpenPod.exe from the extracted location. Keep that filename. Its runtime and supporting files are built in, and unpacking them temporarily can make startup take a moment.

macOS · Apple Silicon and Intel

  1. From the latest release, choose the Apple Silicon DMG ending in macOS-arm64.dmg for an M-series Mac, or the Intel Mac DMG ending in macOS-x86_64.dmg. Apple menu → About This Mac shows your chip or processor.
  2. Open the DMG and drag iOpenPod.app onto the Applications shortcut.
  3. Eject the disk image, then open iOpenPod from Applications. Run the installed copy so the updater can replace it.

The build targets macOS 12.3 or later; testing on 12.3 remains pending. Current downloads are ad-hoc signed and not notarized. If macOS blocks the first launch, review Apple’s guidance for opening apps from outside the App Store and approve only the copy you downloaded from this project.

The matching macOS ZIPs on the release page are used by the built-in updater. For a manual ZIP install, extract the app and move it to Applications before launching.

Linux x64

  1. Open the latest release and download the asset ending in Linux-x86_64.tar.gz. The binary is built on Ubuntu 24.04 and requires glibc 2.39 or later plus desktop graphics and audio libraries. Compatibility with older distributions is not established.
  2. Use your archive manager to extract the complete archive into a folder you can write to, preserving executable permissions. From the directory containing the extracted folder, run:
./iOpenPod/iOpenPod

Keep the whole extracted iOpenPod folder together, including installation.json, current.json, and versions. Always run its top-level iOpenPod launcher, including after an update. In-app updates need write access to this folder.

Update a GitHub installation

iOpenPod checks for updates after opening. To check manually, open Settings → About → Check for updates. About also shows your version and detected Install Channel. A check never installs an update automatically.

Windows & Linux
Choose Update now to download in the background. When ready, save any Library Draft, finish running workflows, close other iOpenPod instances, and choose Restart to install. The app replaces its executable or active version and relaunches.
macOS
Save your work and finish running workflows before choosing Update now. Follow the built-in updater’s download, installation, and relaunch prompts.

GitHub updates verify signed release information and the downloaded archive. Microsoft Store installations use the Store. See below for PyPI installs with uv.

Coming from an older download

If your build only offers Open download page or cannot update itself, finish your work and close iOpenPod, then install the latest release using the native installation steps above. On Windows, replace only iOpenPod.exe; on macOS, replace the app in Applications. On Linux, extract the new archive into a fresh folder and start its top-level launcher instead of copying files over an older bundle.

If a check or download fails, try Check for updates again later or install from the release page. Keep any recovery files until an interrupted update is resolved.

Install through your store

On Windows, get iOpenPod from Microsoft Store. Open the listing, install the app, then launch iOpenPod from the Start menu. The Store handles installation and updates; you do not need a separate Python installation. The Store app requires Windows 10 version 2004 or later, or Windows 11, on an x64 PC.

Mac App Store, Flathub, and Snap Store remain planned. Check the download section for availability.

Store availability is independent: a release on one channel does not mean the others are ready. Sandboxed builds need verified access to your media folders, removable iPod, and external media tools. Their release instructions will explain the required permissions.

Install from PyPI with uv

First install uv, then run:

uv tool install iopenpod

Launch the app with iopenpod. For updates, choose Update now, then Restart to install in the app.

Set up media tools

FFmpeg and FFprobe are required for media inspection and conversion. Chromaprint’s fpcalc enables optional acoustic matching. These command-line tools are installed separately from iOpenPod.

  1. Launch iOpenPod. If tools are missing, the startup popup offers setup. You can close it to continue browsing.
  2. Open Settings → Media Tools to inspect tool status. Choose Set Up Media Tools when offered.
  3. Review the selected package manager, then choose Install Missing Tools. Installation starts only after your choice.
  4. Use Check Again to verify the tools, then retry your scan or sync.
Windows
The native setup helper uses WinGet. Install Microsoft’s App Installer first if WinGet is unavailable.
macOS
The native helper uses Homebrew for your Mac’s architecture. Homebrew and available conversion codecs have their own OS requirements.
Linux
The native helper supports APT, DNF, Pacman, and Zypper. Automatic setup needs a desktop polkit authentication agent. Available codecs vary by distribution.

Existing tools on your PATH can also be used. Installing tools on the host does not automatically expose them inside Flatpak, Snap, or the Mac App Store sandbox; use the instructions for that specific release.

Your first sync

  1. Connect and select your iPod. It must already be mounted and readable by your computer. Choose it in the device picker.
  2. Keep a Backup Snapshot. Use Backups to capture the contents you want to preserve.
  3. Choose Sync with Host. Add your computer’s media folders and choose which media types to scan.
  4. Select your media. Choose what you want on the iPod, then open Review.
  5. Read the changes. Review additions, updates, and any removals. Removal candidates begin unchecked. Choose Sync Selected when ready.
  6. Eject when finished. Use iOpenPod’s eject action and wait for safe removal before unplugging.

Library edits save automatically by default. To review those edits before saving, enable Draft all changes in Settings. Sync has its own review step.

When something needs attention

The iPod does not appear

Check that your operating system mounts the iPod as a drive and can access its files. Open the device picker to refresh discovery. iPod touch, iPhone, and iPod shuffle are not yet supported. On Linux, follow any device-identification setup shown by the app.

Sync reports a missing tool or encoder

Check Settings → Media Tools. FFmpeg must include the encoder selected for your conversion settings. A successful tool installation does not guarantee every optional encoder is included. Correct the tool or encoder choice, then retry.

Linux reports a Qt platform error

The native app needs your distribution’s desktop graphics, XCB, and XKeyboard libraries. Follow the dependency list for the published package and your distribution. Store packages carry a separate desktop runtime and may need different troubleshooting.

A write was interrupted

Reconnect the same iPod and follow the recovery action shown by iOpenPod. Keep recovery files in place until recovery completes. Backup Snapshots are an additional user-controlled copy of your data.

Still stuck? Report an issue with your iOpenPod version, install channel, operating system, iPod model, and steps to reproduce.
